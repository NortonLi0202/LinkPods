# LinkPods v1.1 Release Plan

> **For agentic workers:** Use superpowers:executing-plans to execute this plan inline; perform one final review of the branch.

**Goal:** Publish the user-requested v1.1 APK as a GitHub prerelease.
**Architecture:** Base the release on current main, update version metadata and current documentation, preserve the existing signing identity and fixed payloads, then publish the exact verified commit and APK.
**Tech Stack:** PowerShell, Android SDK/NDK/JDK, Python host checks, GitHub Releases.
**Spec:** User request: publish an APK prerelease and update the version to v1.1.

## Global Constraints

- Application version 1.1, versionCode 102, package lp.pods, minSdk32, ARM64.
- Use release/v1.1; retain historical v1.0 notes and the existing signing identity.
- No device actions, private build inputs, credentials, or generated binaries in Git.
- Preserve incomplete device acceptance and exact adapter boundaries; do not claim stability or completed licensing review.

## Review Focus

Check manifest/project/build metadata agreement, certificate continuity, packaged notices, source-only Git contents, and the published asset digest.

## Task 1: Prepare and verify the release

- [ ] Update manifest, project.json, build checks/output, current Chinese/English docs and v1.1 release notes.
- [ ] Retain actual upstream notices for packaged third-party components.
- [ ] Run project check, existing host tests, full APK build and certificate/metadata/payload verification. A version-only change needs no test mirroring version constants.
- [ ] Review the final diff, commit the release branch, and merge its PR into main after required checks.
- [ ] Tag the verified release commit v1.1, upload APK and SHA256SUMS.txt to a draft, verify uploaded bytes, and publish with prerelease=true.
