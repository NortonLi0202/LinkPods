# 双向音频交接与已让出状态的链路管理

- Status: accepted（补充并修订 [ADR-0001](0001-galaxy-initiated-audio-handoff.md)）

## Context

[ADR-0001](0001-galaxy-initiated-audio-handoff.md) 仅定义了由 Galaxy Tab 发起的单向交接规则，未覆盖反向交接（iPhone 接回）以及平板让出音频后的链路生命周期。真机观察表明，平板让出并断开 A2DP 后会遇到三类相互耦合的问题：一是被动 A2DP 重连在约 40 秒后重新拉回音频，且 Android 无法在 `STATE_CONNECTING` 广播中区分系统/耳机被动重连与用户在系统蓝牙界面手动点击连接；二是让出断开 A2DP 后，AirPods 会从系统输出列表消失，使“系统路由确认目标输出”与“后续自动切回平板”相互矛盾；三是反向交接缺乏明确的让出与防反弹边界，且现有多个分散策略（本地播放、对端路由、音频链路）各自维护局部状态并存在低类别路由杂包误清对端状态等隐患。

## Decision

1. **统一音频归属状态模型**：以单一的音频归属状态机（本机持有 / 已让出 / 观察中）统一驱动音频交接与系统链路控制，取代多个互不知情的分散策略各自猜测。
2. **A2DP 断开时的目标输出边界**：在`自动交接（AUTO_HANDOFF）`下，当平板处于`已让出（Yielded）`状态（A2DP 断开）时，允许平板上确认的新播放自动切回 AirPods；明确放弃该状态下的平板外放保护（若需平板外放，应切换为`纯控制模式（CONTROL_ONLY）`或关闭自动交接）。当 A2DP 已连接且系统路由明确指向其他音频设备时，仍按 ADR-0001 拦截，不抢占外放。
3. **已让出期间严格拦截被动 A2DP 重连**：在`已让出`状态下不再尝试从 `A2DP STATE_CONNECTING` 猜测是否由用户在系统蓝牙中手动发起；任何被动 A2DP 重连一律压制并保持断开。主动切回平板统一通过`手动切换`、保护期外确认的新播放，或切换为`纯控制模式（CONTROL_ONLY）`。
4. **反向交接让出与防反弹保护期**：
   - 当 iPhone 出现明确新播放，或耳机实际音源切至已识别的 iPhone 时（无论中间无音源空窗持续多久，不再使用 1.5 秒时间窗卡死），平板在非通话状态下承认让出、断开 A2DP 并尝试暂停本机正在播放的媒体。
   - 进入`已让出`状态后开启短暂的`防反弹保护期`（约 3–5 秒，具体时长按真机日志校准），保护期内忽略被暂停的同一平板播放器 `PAUSED → PLAYING` 自动反弹，防止立刻抢回耳机；`手动切换`不受此保护期限制。
   - 修复对端路由状态判断，仅路由用途的低类别报告（`category <= 100`）不得清除已建立的对端播放状态，保护双直播场景不被假上升沿打断。
5. **HFP 链路处理边界**：若只读真机诊断证实 HFP（通话配置文件）保持连接是触发被动 A2DP 重连或导致对端起播无声的诱因，允许在平板非通话状态下随让出流程一并断开 HFP，但必须保持`控制会话（ControlSession）`与电量、降噪等控制功能正常可用，且来电时仍按既有流程重连 HFP。

## Considered Options

- **A2DP 断开后禁用自动切回平板（严格外放保护）**：在让出断开 A2DP 后，平板新播放一律不自动接回，仅允许`手动切换`。已拒绝——这会导致平板让出一次后即永久失去自动交接体验，破坏双向无感交接核心场景。
- **继续启发式兼容系统蓝牙界面手动重连**：在 `DISCONNECTED → CONNECTING` 时通过猜测对端是否在播来决定放行或拦截。已拒绝——Android 不提供发起方标识，在耳机切换出现长无音源空窗或对端未报停播时必然产生竞态漏放或锁死。

## Consequences

- 代码重构前须先执行只读真机日志诊断，明确约 40 秒被动 A2DP 重连的发起源（系统蓝牙栈、HFP 联动或 AirPods 固件）、HFP 连接状态及手机 B 站起播无声的完整事件时序，再按本决策与更新后的 [GLOSSARY.md](../../GLOSSARY.md) 一次性重构状态机并校准防反弹时长。
- 用户在`自动交接（AUTO_HANDOFF）`且处于`已让出`状态期间若希望平板走外放，需先切换为`纯控制模式（CONTROL_ONLY）`。
